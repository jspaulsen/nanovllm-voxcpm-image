# Decisions

1. **Packaging repo, not a fork.** Upstream pinned by SHA and patched with `patches/*.patch`; bumping upstream is a one-line change and our diff stays visible. Easier to undo than a fork (can always fork later).
2. **Public GitHub repo and GHCR package** (`jspaulsen/nanovllm-voxcpm-image`), so the image pulls without `docker login`. Started private; flipped public (#4). Upstream is MIT, and the repo contains no secrets (CI pushes with the workflow's `GITHUB_TOKEN`).
3. **Image name** `ghcr.io/jspaulsen/nanovllm-voxcpm-image`, tags: `latest` (main), `sha-<our commit>`, `upstream-<short upstream sha>`.
4. **CUDA 12.8 / torch 2.8** so one image covers sm_86 and sm_120.
5. **Runtime base is plain `ubuntu:22.04`, not a CUDA image.** The torch/nvidia wheels bundle the CUDA user-space libraries and the NVIDIA container toolkit injects the driver; the image sets `NVIDIA_VISIBLE_DEVICES`/`NVIDIA_DRIVER_CAPABILITIES` itself. Runtime apt adds only python3 + headers, gcc (Triton/Inductor JIT) and the FFmpeg 4.4 shared libs (torchaudio 2.8 / torchcodec 0.7 load them). libsndfile comes bundled in the soundfile wheel. Overridable via `RUNTIME_IMAGE`, which must ship Python 3.10 (the venv points at `/usr/bin/python3.10`).
6. **System Python 3.10 in both stages** (Ubuntu 22.04's), so the venv copies across stages unchanged and Triton finds `Python.h` from `python3-dev`.
7. **flash-attn uses the upstream prebuilt wheel.** Its setup.py downloads a wheel matching torch 2.8 / cu12 / cp310 (contains sm_80, sm_90, sm_100, sm_120 cubins; sm_86/sm_89 run the sm_80 code). `TORCH_CUDA_ARCH_LIST` / `MAX_JOBS=4` only matter if it falls back to compiling.
8. **No uv at runtime; CMD is `uvicorn app.main:app`.** The venv is built `--no-editable`, so the `app` package is installed in site-packages and the upstream source tree is not copied into the runtime stage. `fastapi run deployment/app/main.py` needed that tree.
9. **Cache and identity env live in the image** (`HOME=/cache`, `USER=voxcpm`, Triton/Inductor cache dirs, `HF_HOME=/cache/huggingface`; `/cache` is mode 1777), so any uid works without compose; compose only adds mounts. The default user is `65534` (nobody) so a plain `docker run` is not root; compose overrides it with the host uid. No `WORKDIR /cache`: uvicorn prepends the cwd to `sys.path`, and the cache is a writable mount. The HF cache is a separate mount over `/cache/huggingface` so the host's `~/.cache/huggingface` can be reused.
10. **Compose `VOXCPM_MODEL` replaces `VOXCPM_MODEL_DIR`**, since it may now be a Hub repo id. Upstream resolves non-directories with `snapshot_download`.
11. **`uv.lock` is committed here** (upstream commits none). It is generated by the Dockerfile's `lock` target (`docker build --target lock --output . .`) from the patched, constrained upstream `pyproject.toml`, so the resolve uses exactly the build's inputs, and the builder installs it with `uv sync --locked`. Changing `UPSTREAM_REF`, `UV_CONSTRAINTS` or `patches/` without regenerating it fails the build instead of quietly re-resolving. The `lock` target resolves from scratch, so regenerating also picks up newer releases within the constraints.
12. **Compose image is one `VOXCPM_IMAGE` var** (full ref, default `ghcr.io/jspaulsen/nanovllm-voxcpm-image:latest`), not a tag-only var, so the same knob pins a registry tag or selects a local build (`nanovllm-voxcpm-image:local`). `build:` stays so `docker compose build` / `up --build` still work; they tag the build with `VOXCPM_IMAGE`.
